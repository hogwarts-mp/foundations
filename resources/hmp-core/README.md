# hmp-core

`hmp-core` is the persistent server-side spine of the HMP Foundations stack. It owns accounts,
identity links, character slots, scoped groups and JSON metadata. Other resources consume these
APIs instead of creating competing player tables.

It requires `hmp-mysql` and `hmp-lib`. On startup it applies its versioned schema migrations before
accepting player sessions.

## Identity model

The account ID generated by `hmp-core` is the stable ownership key. The current HogwartsMP runtime
only exposes client-announced Steam, Discord and hardware identifiers. Accordingly, the built-in
fallback stores them as `client-steam`, `client-discord` or `client-hardware` with trust level
`asserted`. They must not be treated as proof for sensitive authorization.

A later MafiaHub authentication resource can register a higher-priority server-validated provider:

```js
const Core = Imports.get("hmp-core");

const unregister = Core.identity.register({
    name: "mafiahub-auth",
    resource: "hmp-auth",
    priority: 100,
    trust: "verified",
    async resolve(player) {
        const identity = await validateMafiaHubSession(player);
        return identity && { provider: "mafiahub", subject: identity.id, trust: "verified" };
    },
});
```

After validating ownership, `Core.accounts.linkIdentity(accountId, principal)` links that verified
principal to the existing internal account. An identity already owned by another account is rejected,
never silently transferred.

## Exports

- `status()` reports startup state and session/provider counts.
- `identity` registers and resolves identity providers.
- `accounts` looks up accounts and links additional identities.
- `sessions` exposes connected, initialized account sessions.
- `characters` lists, creates, selects, unloads and soft-deletes character records.
- `groups` manages account/character roles and calculates effective membership.
- `metadata` stores JSON values at account or character scope.

All mutating APIs return promises. See `types.d.ts` for the full contract.

Character records deliberately contain only identity and slot lifecycle fields. Appearance, location,
inventory and other systems should own their own versioned tables keyed by `character.id`.
`hmp-characters` provides the multicharacter UI and appearance handoff using this API.

## Configuration

Create `data/hmp-core.json` in the server working directory when overrides are needed:

```json
{
  "maxCharacters": 4,
  "autoSelectSingleCharacter": false,
  "duplicateSession": "reject-new",
  "duplicateSessionGroup": "admin",
  "duplicateSessionMinimumGrade": 1,
  "kickDuplicateSession": false,
  "identityOrder": ["steamId", "discordId", "hardwareId"]
}
```

Set `duplicateSession` to `allow-group` to permit simultaneous sessions only for accounts whose
configured account-level group meets `duplicateSessionMinimumGrade`. Sessions still select
characters independently, and one character cannot be active in two sessions at once.

`HMP_CORE_CONFIG`, `HMP_CORE_MAX_CHARACTERS`, `HMP_CORE_AUTO_SELECT_SINGLE`,
`HMP_CORE_DUPLICATE_SESSION`, `HMP_CORE_DUPLICATE_GROUP`, `HMP_CORE_DUPLICATE_MIN_GRADE`,
`HMP_CORE_KICK_DUPLICATE` and `HMP_CORE_IDENTITY_ORDER` provide environment overrides.

## Lifecycle events

The resource emits `hmp:session:ready`, `hmp:session:ended`, `hmp:character:created`,
`hmp:character:loading`, `hmp:character:loaded`, `hmp:character:unloading`,
`hmp:character:unloaded`, `hmp:character:deleted`, `hmp:groups:changed` and
`hmp:metadata:changed` for other server resources.
